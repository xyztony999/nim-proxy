## 业务流程：一次中转请求

1. **客户端鉴权**：`PROXY_API_KEYS` 非空时校验 Bearer 令牌，不通过返回 401；为空时是纯透传模式，客户端自己的 Authorization 原样转发上游
2. **选上游密钥**：从密钥池按轮询取一把（进程内循环游标）
3. **转发**：方法、路径、查询串、请求体原样透传；剔除逐跳头；有上游密钥时替换 Authorization
4. **失败换密钥**：上游返回 401/403/429 且还有未尝试的密钥时，关闭当前响应、换下一把重试（每把最多试一次）
5. **回传**：响应是 `text/event-stream` 则流式透传并禁止代理层缓冲；否则整体缓冲后按原状态码、原响应头、原响应体返回

## 业务规则

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 请求体与响应体不解析、原样透传；NIM 升级参数无需改代码 | README.md |
| R-02 | NVIDIA 限速是账户级（免费账户约 40 RPM）；同一账户多密钥共享额度，轮换不提升吞吐，只在多账户密钥之间有效（多账户有封号风险） | README.md |
| R-03 | 仅 401 / 403 / 429 触发换密钥重试；其他错误直接回传 | app.py |
| R-04 | CORS 全开放（来源 / 方法 / 请求头均为 `*`），供浏览器端客户端调用 | app.py |
| R-05 | 交互式文档端点（`/docs`、`/redoc`）关闭 | app.py |
| R-06 | 连接超时默认 15 秒，读超时默认 600 秒（大 `max_tokens` 的流式回复可能持续数分钟） | app.py、.env.example |
| R-07 | 单 worker 运行；密钥轮询游标是进程内状态，重启归零 | app.py、deploy.sh |
| R-08 | 客户端密钥留空等于不鉴权，公网部署不推荐 | .env.example |
| R-09 | 已有 `.env` 在重新部署时保留；`.env` 权限 600 | deploy.sh |
| R-10 | 反代层必须关闭缓冲（`proxy_buffering off`），否则流式输出卡顿或一次性吐出；请求体上限 64m（base64 图片） | nginx-nim-proxy.conf、README.md |
